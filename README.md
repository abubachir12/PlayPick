# PlayPick

Сервис для поиска игр по настроению, свободному времени и предпочтениям.
Стек: Next.js App Router, TypeScript, Drizzle ORM, Neon PostgreSQL. Источник каталога — RAWG.

## Локальный запуск

```bash
npm ci
```

Скопируйте `.env.example` в `.env.local` и заполните DATABASE_URL и RAWG_API_KEY.
Существующий `.env.local` не заменяйте: добавьте только недостающие значения.
`.env.local` и `.env` исключены из Git. Env-файлы не переносятся между компьютерами через ветки.
Коллектор и импорт читают `.env.local`, затем `.env`; переменные окружения имеют приоритет.

```bash
npm run db:migrate
npm run dev
```

Мигратор применяет только ещё не выполненные миграции по журналу Drizzle.
Миграция `0001_rawg_catalog` добавляет nullable-поля и уникальность rawg_id, не удаляя игры.
Если в старой базе есть повторяющиеся rawg_id, миграция завершится ошибкой: сначала вручную
согласуйте записи; автоматически удалять или объединять их нельзя.
Для базы, созданной ранее через `drizzle-kit push`, сначала согласуйте baseline журнала миграций.
Не запускайте SQL миграций повторно вручную.

Сайт: http://localhost:3000.

## API для фронтенда

```http
GET /api/games?search=elden&page=1&limit=20&genre=RPG&platform=PC&sort=rating
GET /api/games/elden-ring
GET /api/catalog/filters
```

- Список — массив Game, карточка — один объект Game. Ошибка — `{ "error": "сообщение" }`.
- `search`: подстрока названия без учёта регистра, до 200 символов; `%`, `_`, `\` — обычный текст.
- `page`: 1–1000000, по умолчанию 1. `limit`: 1–100, по умолчанию 20.
- `genre`, `platform`: точные названия из `/api/catalog/filters`, до 200 символов.
  Фильтры объединяются условием AND. Неизвестное название даёт пустой список.
- `sort`: `title` (по умолчанию), `rating`, `release-date`.
  Рейтинг и дата сортируются по убыванию, null идут последними; затем title и id.
- Заголовки `X-Total-Count`, `X-Page`, `X-Limit`, `X-Total-Pages` содержат пагинацию.
- Пустой список — 200 с `[]`; неверные параметры — 400; неизвестный slug — 404;
  ошибка базы — 500 с безопасным сообщением. Ответы не кешируются.
- `/api/catalog/filters` возвращает `{ "genres": [...], "platforms": [...] }`
  с уникальными отсортированными названиями из локального каталога.

```ts
const response = await fetch('/api/games?search=elden&page=1&limit=20');
if (!response.ok) throw new Error('Не удалось загрузить каталог');
const games = await response.json();
const total = Number(response.headers.get('X-Total-Count'));
```

Тип Game находится в `types/game.ts`. Дополнительные поля:

| Поле | Значение |
| --- | --- |
| rawgId | Внешний ID RAWG, не локальный id |
| releaseDate | Дата YYYY-MM-DD, без времени и часового пояса |
| genres, platforms, tags | Массивы названий |
| rating | Средняя оценка RAWG, 0–5 |
| metacritic | Оценка Metacritic, 0–100 |
| playtime | Среднее время игры RAWG в часах; не гарантированное время прохождения |
| developer, publisher | Названия компаний через запятую |

Дополнительные поля и внешние ID могут быть null у старых или неполных записей.
createdAt/updatedAt — строки JSON. Описание выводите как текст, без dangerouslySetInnerHTML.

API каталога читает локальную БД и не обращается к RAWG при каждом пользовательском запросе.
Фронтенду не нужен API-ключ RAWG. На страницах с данными/изображениями RAWG добавляйте
видимую активную ссылку `https://rawg.io/` с подписью «Данные об играх: RAWG».
Это требование источника: [RAWG API](https://rawg.io/apidocs).

## Получение игр из RAWG

```bash
npm run collect:rawg -- data/rawg-page-1.json --limit 10 --page 1
npm run collect:rawg -- data/rawg-elden.json --limit 3 --search "Elden Ring"
npm run import:games -- data/rawg-page-1.json --dry-run
npm run import:games -- data/rawg-page-1.json
```

Ключ выдаётся в [RAWG](https://rawg.io/apidocs). Имя серверной переменной — RAWG_API_KEY,
без префикса NEXT_PUBLIC_. Локальная проверка подключения: `node test-rawg.js` (2 запроса).

Коллектор получает одну страницу по популярности (`-added`), затем детали каждой игры
для описания, разработчиков и издателей. `--limit`: 1–40 (по умолчанию 10),
`--page`: 1–100000 (по умолчанию 1), `--search`: до 200 символов.
Размер страницы не меняйте при последовательном обходе. Между запусками порядок источника
может измениться; повторные игры обновляются по rawgId.
При `--search` применяется `search_precise=true`, а порядок релевантности RAWG сохраняется
без сортировки по популярности. Это предотвращает подмену искомой игры более популярным похожим названием.
Для точного получения одной карточки серверный клиент также предоставляет `getGame(idOrSlug)`.

Партия из N игр требует N+1 запросов, без учёта повторов. Запросы последовательны,
с паузой не менее 300 мс и таймаутом 15 секунд. При HTTP 429/5xx допускается один повтор;
Retry-After более 5 секунд прекращает запуск, чтобы не повторять запрос раньше указанного срока.
При любой ошибке деталей весь сбор отменяется до записи JSON. Обложки принимаются только
с HTTPS-хоста media.rawg.io. Поле description_raw сохраняется как текст; HTML description игнорируется.

Файлы в `data/` исключены из Git. Выходной файл создаётся эксклюзивно: существующий
файл не перезаписывается. Коллектор не меняет БД и не выводит ключ/URL запроса в ошибки.
Документация API: [RAWG API reference](https://api.rawg.io/docs/).

## Импорт и старые записи

Импорт принимает JSON-массив из 1–100 игр. Обязательны rawgId, slug и title.
Необязательные поля перечислены в таблице выше; coverUrl — HTTPS без учётных данных,
description — до 10000 символов. У одной партии один источник, без повторяющихся ID/slug.
Старый формат с igdbId сохранён для совместимости; RAWG ID никогда не записывается в igdb_id.
У одной импортируемой записи должен быть ровно один внешний ID.

`--dry-run` проверяет формат без подключения к базе. Он не проверяет конфликты с каталогом.
Обычный импорт — одна атомарная параметризованная SQL-команда. Повторный импорт по rawgId
сохраняет локальные id, slug и createdAt. Пропущенные/null-поля сохраняют прежние значения;
пустой массив очищает список, а числовой 0 является полноценным значением.

Если slug занят записью с другим или отсутствующим внешним ID, вся партия отклоняется.
Нельзя автоматически связывать игры по названию/slug. Для начальной ручной записи Elden Ring
сначала проверьте соответствие реальной игре в RAWG и согласуйте её rawg_id.
Для первого наполнения можно исключить конфликтующую игру из партии.

В настроенной Neon-базе 19 октября 2026 выполнено начальное наполнение: 40 популярных игр
и Elden Ring. Для существующей Elden Ring отдельно проверена карточка RAWG с ID 326243,
совпадение названия, разработчика и издателя. Ей присвоен rawg_id с сохранением локального
id=1 и slug=elden-ring. Привязка и импорт выполнены одной транзакцией с проверкой прежних
значений записи. Исходная запись и загруженные JSON сохранены локально в игнорируемой папке data/.
Это состояние общей настроенной базы, а не seed-данные, включённые в миграцию для новых баз.

Публичного API записи нет: запускать импорт должен разработчик на сервере/локально.
Ключ RAWG, DATABASE_URL и env-файлы не должны попадать в Git, браузер или сообщения.

## Проверки

```bash
npm test
npm run test:db
npm run lint
npm run build
```

Unit-тесты проверяют RAWG с подставными HTTP-ответами, не расходуя квоту ключа.
`test:db` проверяет реальный SQL и миграцию в временных таблицах Neon внутри транзакций;
данные и последовательности публичного каталога не меняются. Нужен DATABASE_URL в `.env.local`.
